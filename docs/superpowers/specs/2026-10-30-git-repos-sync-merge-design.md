# Git「仓库 + 同步」合并（v1：远端并入详情）

日期：2026-10-30 · 状态：已实施（三版原型对比后选定 v1「远端并入详情」）

## 背景与决策

Git 页原本是三个子页：加速 / 仓库 / 同步。后两者**共用同一批本地仓库、同一套
分组与同一份取数**，差别只在同步多了「远端一致性」这一层（巡检结果 + 补齐/合并）。
两页并排的代价是：同一仓库要来回切页签才能对上号；巡检结论无法和「待推送 / 脏区」
同屏对照。

评审结论：**删掉独立的同步子页，把远端一致性并进仓库工作台**——仓库页升格为
「源码管理」，一个列表 + 一个详情面板承载全部信息。

三版原型（`designs/git-merge/`：`v1-detail-hub.html` / `v2-overview-first.html` /
`v3-matrix-batch.html`，索引 `index.html`）对比后选 v1：

- v1 保留既有双栏工作台，改动面最小，仓库动作与同步动作同处一栏；
- v2 的矩阵总览在 872px 预览宽度下要压缩列宽，信息密度反而下降；
- v3 的批量修复预览只看不点，价值可参考，但不值得为此重排整页。

## 四个共用决定

1. **一个仓库列表**：分组在原有「需处理 / 待拉取 / 待推送 / 无远程 / 干净」之上，
   本地范围多一组「远端待同步」置顶——只收**本身干净**（无事可做）但主仓/镜像
   还没追上的仓库；脏区/待拉取/待推送留在原组，那些动作本身就会连带修好远端。
2. **推送只有一个目标**：主仓 GitCode。镜像落后一律显示「等待平台搬运」，
   页面上**不给镜像推按钮**（平台单向镜像，直推会绕过主仓）。
3. **分叉绝不强推**：先 `fetch` 再 `merge --ff-only`，真分叉时 git 拒绝，交人工处理。
4. **巡检频率与上次巡检住状态栏**：`自动 5 分 / 自动 15 分 / 手动` 三态循环，
   会话内记忆（不落盘）。

## 数据与动作

- 数据仍是 `gitrepos:syncProbe`（逐远端 `ls-remote` + `rev-list` 分型，只读不动工作区）。
  该通道走**本地注册表**，所以只有本地范围有巡检能力：远程范围的列表不画三点，
  详情远端条改成一句话提示，远端一致性以「获取」后的 ↑↓ 为准。
- `endpointsByPath` 取代同步子页的 `rows`：巡检一次写全量，补齐/合并后只
  `reprobeOne(path)` 单仓重探，避免整页闪烁与二次全量探测。
- 动作：`补齐`（`syncCatchup(path, [remote])`）、`合并`（`syncMerge` + `interpretPull`）、
  `全部推送到主仓`（遍历主仓 `behind` 的仓库逐个补齐，一条汇总 toast）。
  与仓库动作共用一把 `busy` 锁，杜绝多动作并发改仓库。
- 定时器：`自动 5/15 分` 到点同时 `refresh()` + `probeEndpoints()`——远端变了，↑↓ 也常跟着变。

## 视觉

全部走主题令牌，不新增背景层：列表三点沿用同步子页的四色（一致 / 落后 / 分叉 /
探测失败）；远端条是 `--bg-elevated` 圆角 chip 行（角色徽标 + 状态 + 就地补齐），
远端页签是「名称 + 角色 | URL | SHA | 状态 | 动作」的单行网格；平台镜像配置收进
`<details>`，不占默认视野。
