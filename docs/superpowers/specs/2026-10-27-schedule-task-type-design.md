# 定时任务双类型：运维任务 / 日常任务（分类字段 + 模板集切换 + 分区列表）

日期：2026-10-27。标签：`spec 2026-10-27-schedule-task-type`（实现时代码注释与守卫测试用此标签串联）。
需求：定时任务支持新增「运维任务」与「日常任务」两类，默认运维任务。经澄清确认与浏览器
UI 方案比选（用户选定方案 B：标题区切换 + 左侧色条），差异边界如下。

## 0. 已确认的用户决定

- **差异仅体现在分类与模板集合**：执行链路（agent 无头 run、审批、gate、环境解析）零改动，
  两类任务统一走现有 ScheduleEngine。
- 类型影响的只有：新建弹窗的模板 chips 集合、列表分区归属、卡片色条。表单其余字段
  （名称/周期/目标主机/提示/启停）两类完全一致，目标主机均可选。
- 日常任务用**内置通用模板**（不做用户自定义模板库）。
- 列表**分区展示**：运维任务区在上、日常任务区在下，各带小标题与数量；空区整块隐藏。
- 存量任务迁移后**全部归运维**。
- **编辑已有任务时类型锁定不可改**（方案 B 备注口径，用户确认 ok）。
- UI 视觉细节：类型切换开关内嵌弹窗标题栏右侧（新建/日常｜运维两档分段按钮、尺寸缩小），
  卡片左侧 3px 色条区分类型；比选过程稿见会话记录（gitignore 内，不入库）。

## 1. 数据层

- `schedules` 表新增列 `task_type TEXT NOT NULL DEFAULT 'ops'`，取值 `'ops'` | `'daily'`。
  - 建表语句（database.py 的 `CREATE TABLE IF NOT EXISTS schedules`）加列，覆盖全新库；
  - 存量库在 `_migrate_db` 加补列分支（与同表 `last_abnormal_at` 补列同一模式：查表列集合、
    缺则 `ALTER TABLE schedules ADD COLUMN task_type TEXT NOT NULL DEFAULT 'ops'`），
    DEFAULT 'ops' 使存量行自动归运维，无需数据迁移脚本。
- REST（backend/routes/schedules.py）：
  - `ScheduleIn` 加 `task_type: Literal['ops', 'daily'] = 'ops'`；
  - `SchedulePatch` 加可选 `task_type`，但**编辑路由对已存行的 task_type 变更拒绝**
    （传入且与现值不同 → 422；相同值放行，前端保存时带回原值不报错）；
  - 响应模型透出 `task_type`。
- 前端 `src/api/agent.ts`：`ScheduleIn` / `ScheduleRecord` 类型同步加字段。
- 调度引擎 schedule_engine.py **不改**：计算 next_run、触发、审批全链路与类型无关。

## 2. 新建/编辑弹窗（SchedulesView.vue）

- 标题栏：左侧原标题文案（新建为「新建定时任务」，编辑为「编辑任务」），右侧内嵌
  `运维 | 日常` 两档分段开关，视觉沿用弹窗内 sched-option 分段按钮语言、尺寸缩小。
- 新建默认选中「运维」；切换类型**只替换模板 chips 集合**，已填字段不重置；若当前选中态
  停在旧模板上，切类型后模板选中态清空（selectedTemplate = null）。
- 模板集合：
  - 运维 = 现有 templates 数组原样保留（定时巡检、磁盘清理、日志分析等）；
  - 日常 = 新增 3 条内置模板（同数组按 type 过滤渲染）：
    1. 天气/资讯摘要提醒 —— 每日定时生成当天天气与要点摘要提示；
    2. 周报素材汇总 —— 每周五收集本周任务与变更要点，输出周报素材；
    3. 文件归档整理 —— 定时按扩展名/日期归类整理指定目录（只读预览豁免语义不变）。
- **编辑态**：分段开关置灰不可点（title 提示「任务类型创建后不可修改」），仅展示归属；
  编辑 payload 不带 task_type 变更。
- 保存：create payload 带 task_type；标题区开关与「目标主机/提示词」无联动校验。

## 3. 列表分区 + 色条

- `items` 按 task_type 拆两组渲染：`运维任务`（上）、`日常任务`（下），各带小标题与计数；
  区沿用现有排序（后端返回序）。**空区整块隐藏**，两区皆空才显示现有 empty-state。
- 卡片左侧 3px 色条：运维 = 主题强调色 token，日常 = 现有成功/绿语义 token；
  **禁止硬编码色值**，一律取主题 CSS 变量（主题一致性审查口径）。
- 无障碍兜底：分区小标题是主分类信息载体，色条仅为冗余编码（B 方案已知短板，靠分区消化）。
- 卡片内部结构、按钮组、meta 行、历史/执行/AI 诊断等既有行为完全不变。

## 4. AI 工具 schedule_op（backend/agent/tools/builtin/ops_schedule.py）

- `create` 加可选参数 `task_type`（enum ['ops','daily']，缺省 'ops'），透传入库；
  非法值**直接报错**（不做静默归一——分类字段报错比归一更诚实，与「方向只收紧」惯例同源）。
- 入库 data 带上 task_type；`list` 输出行尾附「[运维]/[日常]」标注。
- create 的名称/提示词长度闸门（S7-11）与 next_run_at 同事务落定（审查修复）等既有约束不动。

## 5. 错误处理

| 场景 | 行为 |
|---|---|
| REST 传入非法 task_type | pydantic Literal 校验 422 |
| PATCH 试图变更已存行类型 | 422，文案说明类型创建后不可修改 |
| 工具 create 传非法 task_type | ToolResult 失败，列出合法取值 |
| 存量库无 task_type 列 | 增量 ALTER 补列，默认 'ops'；补列失败沿用启动期既有迁移报错路径 |

## 6. 测试

- 后端：迁移补列后存量行归 ops；REST create 双类型与非法值 422；PATCH 改类型被拒；
  工具 create 带/不带 task_type、非法值报错（pytest，守卫用例挂 `spec 2026-10-27-schedule-task-type` 标签）。
- 前端：SchedulesView 分区渲染（含空区隐藏、存量归运维）、类型切换仅换模板集且不重置已填字段、
  编辑态开关置灰（Vitest + @vue/test-utils，命令沿用项目现有前端测试/类型检查口径）。

## 7. 范围外（YAGNI）

- 用户自定义模板库、按类型差异化审批策略/执行路径、类型间迁移、列表筛选 chip 模式
  （B 方案分区已替代）——均不做。

## 8. 决议记录

- 差异本质四选一 → 用户选「仅分类 + 字段/模板差异」。
- 差异项多选 → 用户仅选「模板集合不同」（目标主机必填性、默认周期差异被否）。
- UI 三方案比选（浏览器并排）→ 用户选 B「标题区切换 + 左侧色条」，事件流 4 次点击均为 B。
- 编辑态类型锁定 → 随 B 方案备注呈现给用户，确认 ok。
