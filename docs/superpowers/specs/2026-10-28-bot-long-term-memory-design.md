# cKunBot 跨会话长期记忆设计

> 2026-10-28 · 让 cKunBot 在不同会话之间记得用户的事。

## 背景

人格内核（表达 DNA / 反应库 / 关系算法 / 底线宪章）解决的是「它是谁、怎么开口」，
但会话本身是无状态的：新建一个会话，它对你一无所知；对同一段关系聊得再久，
换一个窗口就归零。陪伴类产品真正让人舍不得的是「它记得你」。

上一轮调研确认两件事：
- **主聊天并没有消息级操作**（重新生成 / 编辑重发 / 分叉在两边都不存在），
  所以「消息级操作」是净新增，而不是复用；本轮先做记忆这一件护城河事。
- **Agent 侧记忆基建已经齐备**（`backend/agent/memory/`：FTS+向量 RRF 检索、
  失效审计、热度统计、token 预算），陪聊不需要重写一套。

## 目标

- 陪聊能从用户的话里认出可记的事实（称呼、住址、生日、职业、喜好、忌口、家人、宠物、习惯、计划）。
- 下一段会话里，这些事实会作为上下文进入模型 —— 它答得出「你还记得我叫什么吗」。
- 用户全程可控：能看它记住了什么、能逐条删、能全清、能手动补一条。
- 记忆层任何故障都不能影响陪聊本身。

## 非目标

- 不做 LLM 抽取（默认走确定性规则；召回率提升留作后续开关）。
- 不做记忆的 TTL / 过期清理（`memories` 表没有过期字段）。
- 不做跨人格共享记忆（记忆跟着人格走）。
- 不做语音 / 图片记忆。
- 不动 Agent 侧记忆代码（只复用它的表与接口）。

## 平台能力事实（已核实）

| 事实 | 依据 |
|---|---|
| `memories` 表带 `scope` 自由文本列 + `kind` / `source` / `status` / `importance` / `superseded_by` | `backend/database.py:898-919` |
| `mstore.add_memory(...)` 写入并自动 `_fts_sync`；`retire` / `supersede` / `mark_injected` 齐备 | `backend/agent/memory/mstore.py` |
| `retriever.search(query, scopes=...)` 按 scope 过滤，未命中 embedding 自动降级纯 FTS | `backend/agent/memory/retriever.py` |
| Agent 的注入路径强制带 scope：`context_scopes()` → `['global','host:{sid}']`；兜底 `recent_fallback_lines` 也带 scope | `routes/agent.py:724,860` |
| Reconciler 只消费 `memory_jobs` 队列（我们不投递），不会碰人格记忆 | `agent/consciousness_tick.py`、`reconcile.py` |
| FTS5 可用时 `memory_v2.fts='1'`，否则自动退化为词重叠（仍带 scope 过滤） | `database.py:980-986` |

结论：**`memories.scope` 隔离是代码级保证，不是约定** —— 人格记忆不可能串进 Agent run。

## 核心模型

### 写侧：确定性规则抽取

```
用户消息 ──▶ 敏感信息拦截 ──▶ 负向指令判定 ──▶ 11 条规则扫描 ──▶ 事实列表
```

- **只挖用户的话**，不挖助手的复述（那可能是它的幻觉）。
- **宁可漏记，不可乱记**：记错会让它说出用户没说过的话，直接违反人格宪章的诚实边界。
- **零额外模型调用**：每轮不多一次 LLM 往返，延迟与成本不变。

规则表（标题 / 触发 / 产出 / 重要度 / 槽位）：

| 标题 | 触发 | 产出 | 重要度 | 槽位 |
|---|---|---|---|---|
| 称呼 | `我叫X` / `我的名字是X` | 用户叫X | 0.9 | single |
| 居住 | `我住在X` / `我在X` | 用户住在X | 0.85 | single |
| 生日 | `我生日是X` | 用户的生日是X | 0.9 | single |
| 忌口 | `我不爱吃X` / `我不喜欢吃X` | 用户不吃X | 0.85 | multi |
| 厌恶 | `我不喜欢X` / `我讨厌X` | 用户不喜欢X | 0.85 | multi |
| 喜好 | `我喜欢X` / `我爱吃X` | 用户喜欢X | 0.8 | multi |
| 职业 | `我是X工程师` | 用户的职业是X | 0.8 | single |
| 宠物 | `我养了只猫` | 用户养了猫 | 0.8 | multi |
| 家人 | `我女儿叫豆豆` | 用户的女儿是豆豆 | 0.85 | multi |
| 习惯 | `我每天早上跑步` | 用户的长期习惯：早上跑步 | 0.8 | multi |
| 计划 | `周末要去看展` | 用户的计划：看展 | 0.8 | multi |

槽位语义：**single**（称呼/住址/生日/职业）同一时刻只应有一条，新事实让位旧的
（`mstore.supersede`，旧行 `status='superseded'` 并指向新行）；**multi**（喜好/忌口/家人/计划）可并存多条。

噪声控制：
- 捕获组有长度上限（≤12 字），且拒绝含 3 个以上连续重复字（「我喜欢很很很…」不是事实）。
- 居住语境有词表黑名单（「我在开会」不是「用户住在开会」）。
- 否定式优先于肯定式（「我不喜欢吃香菜」只记成不吃，不记成喜欢）。

**敏感信息整条不抽**（不是脱敏后抽，那等于存了一份残缺事实）：
身份证 `\d{17}[\dXx]`、银行卡 `\d{16,19}`、手机号 `1[3-9]\d{9}`、
密码/密钥类 `(密码|口令|api key|token|secret|私钥|密钥)\s*(是|为|:|=)?\s*\S{3,}`、门牌号。

**负向指令**：
- 「别记这个 / 不用记 / 别记下来」→ 本轮一句都不记。
- 「忘掉我说过的火锅」→ 定向删除含「火锅」的记忆；同句里的其他事实照记。
- 指代词（这个/那个/这些）不算可删除对象。

### 读侧：检索与注入

```
query = 当前用户消息
  ↓ ① FTS（scopes=[persona:{id}], kinds=[persona_fact]，无 embedding）
命中 → 按相关度排序，只取命中项
未命中 → ② 单字重合度排序（中文 bigram 桥接不了问句与事实）
仍未命中 → 取该人格最近 3 条（陪伴场景里「它确实记得」比相关性更重要）
  ↓
渲染成「- 用户喜欢辣」这样的人话（不带记忆 id）
  ↓
作为一条独立 role='system' 消息，插在人格 prompt 之后、历史之前
```

**为什么需要第二路单字重合度**：记忆表的 FTS 索引是中文 bigram
（`memory_fts(mid UNINDEXED, tok)`，token 形如 `用户 户叫 叫小 小林`）。
问句「你还记得我叫什么吗」的 bigram 是 `你还 还记 记得 得我 我叫 叫什 什么 么吗`，
与「用户叫小林」的 bigram **零重合** —— 纯 FTS 永远答不出「你还记得我叫什么吗」。
第二路按「查询里出现了多少个记忆中也有的字」排序（去掉虚词与疑问词），
把「用户叫小林」顶到第一位。同分时保持新→旧，于是更近的记性优先。

注入形态（最终选择）：**独立 message 角色**。

```
[0] system  人格 9 节（身份→性格→背景→表达DNA→长度→关系→此刻→拒绝方式→排版→宪章）
[1] system  关于对方，你记得这些事（当事实用，别主动罗列，也别编造没记住的）：\n- 用户喜欢辣
[2..] user / assistant 历史 40 条
```

用 `system` 角色而不是 `user` 角色：事实是「关于对方的信息」，不是对方说的话 ——
混进 user 角色会让模型以为那是用户刚刚讲的台词。

**记忆块不写进 `bot_messages`**：它是对模型的补充，不是一次对话，
写进可见记录会让时间线里凭空多出一段没人说过的内容。

token 预算：`cap_text_tokens(block, 200)` 封顶；记忆为空时不追加任何消息（零开销）。

### 作用域隔离

| 维度 | 值 |
|---|---|
| `scope` | `persona:{persona_id}` |
| `kind` | `persona_fact` |
| `source` | `bot_chat` |

三者共同构成命名域：即使将来 Agent 侧要列全部记忆，也能一眼排除人格记忆。

## 数据模型（复用 `memories`，不新建表）

| 场景 | 写入方式 | 结果 |
|---|---|---|
| 新事实 | `mstore.add_memory(status='active')` | 新增 active 行 + FTS 同步 |
| 同一事实重复出现 | 命中已有 `content` | 跳过，不重复写 |
| 单值事实变化 | `mstore.add_memory` + `mstore.supersede(old, new)` | 旧行 `status='superseded'`、`superseded_by=new` |
| 忘记 | `mstore.retire(status='invalidated')` | 失效不物理删，留审计行 |
| 手动添加 | `mstore.add_memory(title='手动添加')` | 同新事实 |

读侧只查该 scope 且 `status='active'` 的行（失效与被取代的行天然不在召回范围）。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/bot/personas/{id}/memories` | 列出该人格记住的事（id / title / content / created_at） |
| POST | `/bot/personas/{id}/memories` | 手动补一条（body: `{content}`，≤200 字） |
| DELETE | `/bot/memories/{mid}` | 单条忘记（只允许动 `kind='persona_fact'` 的行） |
| POST | `/bot/personas/{id}/memories/clear` | 全部忘记，返回失效条数 |

人格不存在一律 404；空内容 422；重复删除已失效记忆 404（不静默成功）。

## 前端

人格编辑器新增第六区「**它记得你什么**」（`src/components/bot/PersonaEditor.vue`）：

- 只对已有人格开放（新人格没有记忆可看）。
- 列表：内容 + 记下的时间 + 单条「忘记」。
- 手动添加：输入框 + 「记住」。
- 「全部忘记」。
- 读取失败只在记忆区提示，不影响人格本身的保存。

聊天界面**不做任何改动**：记忆对用户不可见才是陪伴感的样子，
「它突然记得」比「它有个记忆面板」自然。

## 错误处理与降级

| 故障 | 行为 |
|---|---|
| 召回抛异常 | 记 warning，当作没有记忆，回复照常 |
| 写入抛异常 | 记 warning，本轮不记，回复照常 |
| `memories` 表不存在 / SQLite 锁 | 同上（异常被兜住） |
| FTS5 不可用 | 自动退化为词重叠，功能可用、相关性变差 |
| 模型调用失败 | 既有行为不变：不落库助手消息，不写记忆（记忆只在助手消息落库后才写） |

## 测试

后端（`backend/tests/test_bot_memory.py` 18 例 + `test_bot_service.py` 5 例 + `test_bot_routes.py` 5 例）：

- 抽取：11 类规则各一例、否定优先、敏感整条不抽、负向指令抑制、闲聊不误采。
- 存取：scope 隔离、重复不重写、单值槽位取代（校验 `superseded_by`）、定向遗忘、全清。

- 降级：记忆层抛异常时回复照常产出。
- 路由：四个端点的形状与 404 / 422 分支。

前端（`src/components/bot/PersonaEditor.guards.test.ts` 4 例）：编辑器有记忆区、
只对已有人格开放、API 有四个端点、聊天界面不出现记忆控件。

## 成功标准

1. 说「我叫小林，我住在杭州，我喜欢吃辣」→ 换新会话问「你还记得我叫什么吗」→ 答得对。
2. 说「别记这个」→ 该轮不产生任何新记忆。
3. 说「忘掉我说过的火锅」→ 相关记忆被失效。
4. 人格 A 的记忆不出现在人格 B 的注入里，也不出现在 Agent run 的注入里。
5. 关闭 FTS5 后功能仍可用。
6. 记忆层抛异常时陪聊回复不受影响。
7. 记忆块不出现在 `bot_messages`。

## 假设与依赖

- 复用 `backend/agent/memory/` 的表与接口；不改 Agent 侧任何代码。
- `memories` 表已存在且 `memory_v2.fts` 闸门已就位（`database.init_db` 负责）。
- 前端不新增依赖；沿用 `botApi` 与既有按钮样式。

## 风险与已知取舍

- **规则式召回有限**：只抓显式陈述，隐含事实（「我最近很累」）记不到。缓解：后续可加 LLM 抽取开关（默认关），规则路径不动。
- **共享表带来的耦合**：人格记忆会出现在 Agent 侧的全量记忆视图里（若有该 UI）。缓解：kind / source / scope 三重命名域可过滤。
- **本地与 QQ 共享同一 scope**：同一人格在两端记忆互通（人格是同一个存在）。若产品要隔离，scope 需要再带 channel。
- **计划类事实会过期**：`memories` 无 TTL 字段，本轮不清理，靠重要度与最近命中自然压制。
- **误记的代价高于漏记**：抽取规则刻意偏保守；宁可它偶尔想不起来，也不要它张口就来。
