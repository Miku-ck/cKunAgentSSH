## 1. 问题陈述

现在的首页是 `SshView.vue:96` 的 `.quick-start` —— 一个启动器：搜索框 + `本地终端` / `远程连接` 两组卡片，作用只是"开一个终端"。它带来三个问题：

1. **产品的主角没有入口。** AI 指令面板（`SshAiPanel` → `SideChatPanel`）是这个应用的核心能力，但它藏在右侧 460px 面板里，且必须先有一个活动会话才顺手；用户打开应用看到的是"选一个 shell"，不是"说一句话"。
2. **执行过程无处安放。** 一条指令跑起来后，计划、工具调用、diff、审批、结果全部挤在右侧消息流里，和"聊天"混在一起；`AgentRunPanel.vue` 有 `任务规划` / `审批队列` 的结构，但它是浮层卡片，不是可以停下来看的视图。
3. **待办会漏。** 审批请求散在各自会话的面板里，用户切走标签就看不到"有几条卡着等我放行"。

值得做：首页改成**下达 + 汇总**两个职责，过程交给独立的**运行视图**。

## 2. 方案概述

三态，互斥地占据主区（标题栏 / 标签条 / 快捷命令条这三层外壳不变）：

```
首页      下达 + 跨 run 汇总        输入卡 → 待你放行队列 → 右栏上下文
运行视图  过程与轨迹                run-head → 左计划时间线 | 右事件流（审批就地内联）
终端      原始终区                  快捷命令条只在这一态出现
```

- **首页成为标签条第一个标签**：默认打开、不可关闭；会话标签排在它后面。取代现在用 `＋` 按钮当"回首页"入口的做法（`SshView.vue:25-35`，`＋` 回归"新建终端"本义）。
- **首页只留两件事**：指令输入卡、`待你放行` 汇总队列。删掉 Quick Start 的搜索与卡片组，删掉复盘区（上次指令 / 历史列表）——复盘属于运行视图与既有的 `历史任务`。
- **运行视图不新建数据源**：读 `stores/agent.ts` 已有的 run 状态（`status` / `currentState` / `iteration` / `ToolCallEntry[]` / `clarificationWizard` / `snapshot()`），只是给它一个能停下来看的版面。
- **手记（atelier）作为新增主题**，不改现有 7 套主题的令牌名：米纸底 / 墨线 / 朱砂强调 / 衬线字 + 本地字体优先。布局与主题层解耦，同一版面在现有深色主题下也必须成立。

### 运行视图 · 轨迹

15. 作为运维，下达后自动进入这条指令的运行视图；标签条上它占一个标签，标题是指令摘要，可关闭。
    > 修订 2026-09-30：标签、摘要标题、可关闭都落了；**"自动进入"没做**。它是一个跨层决定：导航层要为"有一条 run 起来了"这个信号去 watch agent store（还是由下达方显式调 openRunView），而这条通路会同时改变首页与侧栏两条下达路径的既有行为 —— 与"保持现有逻辑不变"直接冲突。先做成点标签进入，自动进入单独一片裁决后再补。
16. 作为运维，运行视图顶部固定显示：指令原文、`● 运行中 + 计时`、`第 n/m 步`、trace 号、目标主机链、模型与审批方式、`回首页`、`中止`。
    > 修订 2026-09-30：`第 n/m 步` 落成 **`第 n 步`**。m（总步数）在 run 结束前不存在：`totalIterations` 来自 done 事件，`maxIterations` 是前端自己发出去的值、后端不回传（见 §8 表）。把发送值当分母印出来，就是一个借来的假上限。
    > 「模型与审批方式」两项**没进头部**：run 没记录自己是用哪个模型、哪一档跑的，那两个值此刻只有"设置面板里的当前选择"。把当前选择标成这一轮的档位是另一种串台（运行中改设置会改写历史外观）。要补就得像 `lastTask`/`lastSshSessionId` 那样在发起时一次性记下（见任务清单：run 归因字段）。
    > 修订 2026-09-30（`baeab01`）：两项都进头部了，走的就是上面那条路 —— `lastModelId`/`lastPermissionMode` 与 `lastTask` 同批在 `runAgent` 里写入。两个细节：审批档的缺省值取 `PERMISSION_MODE_DEFAULT`，与 `streamAgentRun` 发出去的是同一口径（一处写 `'normal'` 两处抄会对不上）；模型名只在模型列表里查得到才渲染，列表未拉到或模型已删时那一格空着，不印内部 id、也不拿当前选择顶上。
17. 作为运维，左栏是计划时间线：每步一个状态（完成 / 等待 / 未开始）与耗时，纵向连接线串起来。

## 4. 已定决策

| 决策 | 取舍与理由 |
|---|---|
| 首页 = 指令面板，Quick Start 整块退役 | 启动器职责由 `＋` 新建终端 + 远程管理页承担，不需要占一屏 |
| 首页是标签条第一个、不可关闭的标签 | 而不是"一个覆盖层"。现在 `showHome` 是覆盖标志，导致首页与标签态互相压制（`SshView.vue:13,42,49,57` 到处 `&& !showHome`）；做成标签后这个特例可以消掉<br>> 修订 2026-09-30：标签落地了，`&& !showHome` **没全消掉**，也不该消：`:visible` 上的那一处是 xterm 的 fit 闸门（RemoteTerminal.vue:437 用它兜底）——终端在 `display:none` 的容器里 fit 出来是 0 尺寸。消掉它要的是真正的分栏 panes 模型，不是改个表达式 |
| 首页不放复盘、不放历史 | 用户明确判定为冗余：字段与审批卡重复，且复盘的归属是运行视图 |
| 轨迹独立成视图，不塞进右侧消息流 | 消息流继续承担"问答"，运行视图承担"过程"；两者数据同源不复制 |
| 审批在首页汇总、在 run 里就地出现，**同一对象** | 汇总解决"切走就漏看"，就地解决"跳上下文"。状态仍由 agent store 单点持有 |

| `＋` 收纳全部上下文入口 | 用户判定：上下文是动作不是状态，不该常驻底栏 |

| 手记做成新主题而非改现有主题 | 令牌名不变，只加一组 `data-theme` 覆盖，A/B/C″ 那几版布局可复用同一版面 |

## 5. 测试决策

**接缝（尽量复用，不新建）**

- **S1 `stores/agent.ts` 的 run 状态 + `snapshot()`** —— 轨迹的唯一数据源。运行视图只读它。断言"时间线步数 = 计划步数""事件顺序 = `ToolCallEntry` 顺序""中止 → 状态 failed"都落在这里，不需要碰组件。
- **S2 `useSshNavigation`** —— 视图态唯一出口。新增：首页标签恒在且不可关、`run` 标签的开/关/激活、快捷命令条可见性由"当前是否终端态"派生。现有 `showHome` 的覆盖语义改为标签态。
  > 修订 2026-09-30：落地时新增同层 composable `useHomeTarget` 承载目标主机派生（`targetLabel` / `options` / `pick` / `canBulkDispatch`），单测 9 例。它刻意与 `useSshNavigation` 分开：后者管"在看哪一屏"，前者管"指令打到哪台机器"，合成一个会诱使人在换目标时顺手切走首页。Quick Start 的搜索/过滤 state（`qsSearch` 等）随之从导航里删掉，能力移入 ＋ 菜单组件。
- **S3 待放行队列** —— agent store 已有 `pendingPermissions`（`agent.ts:199`）派生视图，直接复用，不新增可变状态。断言：计数、批准/拒绝后离开队列、失败留卡可重试、重复点击不重复发请求。**"拒绝优先于自动审批"不在此接缝**（见故事 13 修订：它是后端 `PermissionGate` 的接缝）。
- **S3b 结算下沉** —— `approvePermission(id, scope)` 提进 agent store（原先在 `AgentRunPanel` 组件内），返回三态 `granted | skipped | failed`：布尔会把"用户重复点击"报成"授权失败"。用户可见层的两个入口（侧栏托盘 / 首页队列）共用 `useApprovalActions`。
- **S4 主题令牌** —— 新增 `data-theme="atelier"` 的变量覆盖，断言"每个被引用的 `--*` 都有定义"，防止手记主题下出现 `undefined` 色。

**完成长什么样**

- `npx vitest run` 全绿，且 S1–S4 各有新增用例；`npm run typecheck` 零错误。
- 组件层不写快照测试（项目现状只测 store/composable/util，组件测试仅 `NvGauge` 一例）；版面正确性靠预览稿对照 + 手工验收第 1–26 条。
- 手工验收必过三条：断网加载首页字体不塌；快捷命令条在两态下的显隐；首页与 run 里点批准效果一致且计数同步。

## 6. 明确不做

- **并发多 run。** agent store 的 `status` / `runId` 是单例，一次只跑一条。多 run 并行需要后端与会话模型改造，另案。
- 不改后端 SSE 协议、不改 `streamAgentRun` 事件形状。
- 不改审批语义（哪些算高危、`始终允许` 的授权范围），只改它出现在哪儿。`approval-scopes` 原样复用。
- 不动 SFTP 续传损坏（S5-01）与补全写进活 shell（S6-01）两个 Critical——它们与本改动无关，另案处理。
- 不做终端分屏 / tmux 复用。
- 不做浅色主题下手记配色的全量适配（先保证深色 + atelier 两套）。
- 不把预览稿 A / B / C″ 三版落地。
- **不做带行号的 diff 卡与快照路径**（故事 18 的后半句）。核过：前端没有任何 diff / patch / 快照路径字段，后端把工具结果 `str()` 后作为纯文本下发（`routes/agent.py:953-955`），SSE 里也没有这类事件。要做等于无源，只能先改后端 —— 那超出"不改 SSE 协议"（§6 第二条）。写操作卡降级为「命令 + 纯文本输出 + 风险与可逆性角标」，等后端补字段再单独一片。
