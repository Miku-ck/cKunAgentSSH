# cKunBot — 虚拟陪伴角色子系统（架构与决策记录）

cKunBot 是标题栏「Bot」入口（`Ctrl+Shift+9`）的虚拟陪伴角色：有性格、有记性、有分寸的聊天对象。与运维 Agent **零打通**——不执行命令、不调用工具，只共用模型配置与 `memories` 存储底座（靠 scope 隔离）。本文记录架构分层与关键取舍；术语口径见 [CONTEXT.md](../CONTEXT.md)。

## 分层

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 人格 | `bot/character.py` | 诚实宪章（不可编辑、压尾）、情境反应库、阶段指南、注入/泄露兜底口径 |
| 表达 | `bot/voice.py` + `bot/stickers.py` | 表达 DNA（6 档位 → 可执行约束）、去 AI 味清洗、分条切分；表情包标记校验与收口 |
| 关系 | `bot/relation.py` | score 记账（只增 + 读时衰减）、阶段唯一口径、升温档参数 |
| 状态 | `bot/state.py` | 7 轴心理状态：事件→增量（0 次额外模型调用）、软饱和、冷却、基线回归、pacing |
| 记忆 | `bot/memory.py` | 事实抽取（11 类正则）、召回（FTS+单字+向量融合、三重门控）、保守衰减与容量边界 |
| 主动 | `bot/proactive.py` | desire、四重抑制闸（统一 12h 口径）、确定性选题器、分渠道投递（召回 → 主动 → 寄存）、调度器（60s 轮询，兼记忆维护心跳）；群聊按**会话级** 12h / 日 2 条配额；`probe()` 是同一套闸的手动探口（算而不拦） |
| 群可参与期 | `bot/group_ambient.py` | @ 之后 5 分钟窗口、60s 接话节流、近期群消息临时上下文（不落库）；群友发言只作现场，不进记忆/关系/状态；`GROUP_MODES` / `ambient_allowed()` 是群参与档的唯一事实源 |
| 渠道 | `bot/provider.py` + `channel_runtime.py` + `qq_*.py` | 5 成员 provider 协议；每机器人独立线程/长连接；入站管线平台无关；群回复有两条发送通道（带 `msg_id` 的被动 @ / 不带的主动不 @） |
| 会话 | `bot/chat_service.py` + `inbound_pipeline.py` | 分节 prompt 组装、流式回复、幂等/超时兜底/分段投递 |

## 不变量（改代码前先读）

1. **宪章压尾且不可被人格字段覆盖**。人格自由文本以「设定材料」身份进 prompt（声明分区在材料之前），保存时覆盖类注入直接拒绝（`persona_text_risk`）。
2. **阶段只有一个口径**：relation 的 score。UI 进度条、`你们的关系（…）`、状态段里的「关系」全部同源；`describe_state` 的 stage 由调用方显式传入。
3. **状态层 0 次额外模型调用**。事件→增量是纯函数，可重放可单测；不引入「让模型自报状态」。
4. **人格记忆隔离**：所有维护 SQL 限定 `scope=persona:{id} AND kind='persona_fact'`；降权不碰 `updated_at`（与 `mstore.decay_memories` 同口径）。
5. **记忆宁漏不瞎编**：抽取走正则（可精确断言），敏感信息整条不抽，投毒话术不得成为事实；召回失败一律当没有记忆，绝不拖垮回复。
6. **QQ 协议内合规**：被动回复窗口内回复；主动「心里话」按渠道分档——local 直投、QQ 单聊先试互动召回（`is_wakeup`，30 天内 4 个周期各 1 条）再发普通主动消息、群聊发不带 `msg_id` 的主动消息（无召回能力，每群独立 12h / 日 2 条，且人格的群参与档得开到 `proactive` 才进巡检清单），无权限一律寄存在 48h 内捎带。频率统一「约 12 小时一次」（`MIN_INTERVAL_H=12`，日配额 2 只当天花板），平台拒绝（无权限/拒收/离线）一律退回寄存，不硬编造重试；频控/内容/网络一类失败不占配额，但按会话退避 30 分钟，不许每轮重烧模型。详见 [主动 spec](superpowers/specs/2026-10-30-qq-proactive-message-design.md)。
7. **群里先过「群参与」档，再谈接话**：档位长在人格上（`group_mode`，默认 `mention_only` = 只 @ 才答），不在机器人连接上 —— 渠道与人格是 1:1，两处口径必有一个漂移。档位在 `ambient` 及以上才允许接话，且只在「@ 过 + 5 分钟内」距上次开口 ≥60s 时接一句；接话不写用户消息、不抽记忆、不记关系、不动状态轴，只落机器人自己那句。接话给真回复让位（会话锁被占就作废、预算只有 45s），也不接机器人自己发的消息、不接重投的同一条事件。要做到这点需群主在手机 QQ 开「接收全量消息能力」，未开则退化成只有 @ 有反应。详见 [群聊 spec](superpowers/specs/2026-10-30-qq-group-ambient-design.md)。
8. **想看主动效果不必先聊熟**：`POST /bot/proactive/probe`（只读侧会话栏的「试一句」，只挂在 QQ）把意愿分、12h 间隔、静音窗、日配额、冷场冷却**照算一遍但不拦**，真发一句并把账本上那一行念回来——回显与落库同源。落账、间隔、配额全部照占，不拿「只是试一下」骗自己；唯一豁免是冷场冷却（账本 `reason` 带 `manual:` 前缀）：试发不是「她自己想说话」，没人接不该把人设冻 48h。微信没主动通道，当场 409 比默默寄存一句永远发不出去好。
9. **群里 @ 不 @ 人是通道选择，不是文案**：平台没有「不要 @」参数，「回复某人」是它给带 `msg_id` 的被动回复自己加的样式。人格的 `mention_sender`（默认开 = 照旧 @，升级不改观感）关掉后这句改走不带 `msg_id` 的群主动消息；只有平台明确拒收（`permission` / `invalid`）才回落被动回复（宁可带 @ 也不让这句消失），`network` 不回落——发没发出去不确定，回落就是群里同样的两句。开关只给群会话生效，通道判定读会话快照（@ 回复是热路径，不为一个开关再查一次表；旧快照缺字段按默认照旧 @）。出站一律 `strip_at_markup` 抹掉模型照抄的 `<@…>` / `<at id=…></at>`：QQ 纯文本里那串不是 @，是给人看的源码。
10. **人格自由文本分区自带用法口径**：光把「是什么」写进 prompt（`你的喜好与雷区：X`）等于递给它一份待播报的话题清单——接不上话时最省力的走法就是拐回自己的喜好（真机反馈：没人问也老自报喜好）。所以标题里就得说清「什么时候才拿出来」，且口径排在正文之前（内容后面再补规矩，模型已经把那一节当清单读完了）。喜好不能被整节删掉：被问到、或话正好接到那儿时，它还是这个人的一部分。见 `chat_service._system_prompt`。

## 记忆治理（2026-10-29 决策）

- **衰减策略（保守）**：闲置超过半衰窗（45 天，锚点 `last_used_at`，从未注入退回 `created_at`）的记忆，每次维护最多下调一档（×0.5），地板 0.1。**只降权、不删除**；重复维护会继续淡化直至地板——这是「想不起的渐淡」，不是误伤。
- **豁免**：pinned（用户置顶）与关键事实（importance ≥ 0.85，覆盖称呼/生日/住址）永不衰减、不参与淘汰。
- **自进化回路**：被注入一次 importance +0.1（封顶 1.0）——「常想起的更牢，想不起的渐淡」。
- **容量边界**：每人格 200 条硬上限；超限按「最低热度（use_count）+ 最旧」淘汰，走 `mstore.retire(reason='bot_decay')` 留审计行，不物理删。
- **触发时机**：挂在 `ProactiveScheduler.tick` 尾部（60s 一轮、每轮最多一个人格、轮转、小事务），聊天热路径零阻塞；治理失败只记日志。
- **为什么不做 Agent 侧那套「跌破地板即 retire」**：陪伴场景漏一条记忆是可惜，错删一条是事故；保守策略 + 容量上限双保险足够。

## 安全边界（2026-10-29 决策）

| 威胁 | 防线 | 位置 |
| --- | --- | --- |
| 人格字段注入（「忽略以上设定」） | 保存时拒绝（可读错误）+ prompt 分区声明 + 宪章压尾 | `routes/bot.py` 校验器、`chat_service._system_prompt`、`character.persona_text_risk` |
| 记忆投毒（话术借抽取规则成为事实） | 事实内容过注入检测，命中即丢弃 | `bot/memory.extract_facts` |
| 输出泄露（复读口令/证件号） | 落库前按句删除命中敏感口径的句子；全文塌掉给占位句不给空串 | `character.strip_sensitive_lines`，接在 `strip_ai_smell` 之后 |
| 渠道凭据泄露 | SQL 读出口把 `app_secret` 折叠成 `has_secret` 布尔，密文不进 Python 对象；明文只在拨号时解密 | `database._BOT_CHANNEL_SELECT`、`get_bot_channel_secret` |
| 失效保护 | 选题/衰减/安全清洗全部 try-except 降级（清洗失败放行原文并 warning），与「记忆失败不影响回复」同一哲学 | 各模块调用点 |
