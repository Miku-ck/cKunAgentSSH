8 · 本页的盲区：scoped 属性可达性（另行核验）IMPORTANT

本页的 CSS 是把 <style scoped> 从源码抽出来、剥掉 :deep()、 再重新作用域到 .nv-scope 的。因此本页在结构上无法暴露"scope 属性挂错元素"这类缺陷： 只要源码里写了规则，本页就一定显示它生效。而这类缺陷恰恰会让真机上的进度条整条不显示。

机制：父组件样式要命中子组件内部元素必须走 :deep()。 漏写会编译成 .nv-gauge > .nv-bar[data-v-x] —— scope 属性被要求挂在 .nv-bar 上，而它位于子组件 NvGauge 内部、永远没有该属性 → 这条规则命中 0 个元素。产物里 grep 得到 height: 12px，页面上却是 0 高。

规则编译后形态结论
.nv-gauge > .nv-bar [data-v-…] .nv-gauge > .nv-bar ✓ 属性作为祖先前缀，能命中
.nv-gauge > .nv-trend [data-v-…] .nv-gauge > .nv-trend ✓ 属性作为祖先前缀，能命中
  • ✓ 来自真实 SSR 输出的事实：.nv-gauge（子组件根元素） 带 scope 属性，其内部 .nv-bar 不带 scope 属性 —— 这就是"必须写 :deep()"的根据。 .nv-gauge → 有 · .nv-gauge > .nv-bar → 无
  • ✓ 核验脚本 verify-scope-selectors.mjs：用 jsdom 的选择器引擎，在真实 SSR DOM 上 逐条执行构建产物里编译后的选择器；对每条同时算"带上 scope 属性"与"剥掉 scope 属性" 的命中数，剥掉能命中、带上命中 0 即属性挂错的指纹。 修前它点出这两条规则（剥掉后各能命中 14 个元素，带上后 0 个），修后归零。 本面板 scope 规则 54 条：命中 53；属性挂错 0；目标不存在 1
  • ✓ 产物级核验 verify-nvgauge-bundle.cjs 已补两条负向断言： .nv-gauge > .nv-bar[data-v-*] 与 …> .nv-trend[data-v-*] 形态必须不存在。 该脚本原先默认先剥掉 [data-v-*] 再断言 —— 那正好销毁了"规则能否命中"的 唯一信息，是本轮把缺陷放过去的原因
