1 · 背景层级：最终收敛为「两层」

原始实现中 --bg-base / panel / surface / elevated / input 五层全为 #000000，卡片只能靠 1px 边框区分。 先建立四级坡度修复"无层次"，随后按要求收敛为两层：除卡片外一律 --bg-base。

最终形态的令牌集（深色默认主题）

--bg-base#000000
--bg-elevated#1a1a1e

两层的亮度比 1.21:1 —— 卡片清晰浮起，且结构背景不再分散注意力。 #1a1a1e 取自代码中 12+ 处已存在的 fallback 值（var(--bg-elevated, #1a1a1e)），即原作者的预期值。

2 · 归入规则（本次实际执行的映射）

"卡片以外的背景颜色都用 --bg-base" 落到代码上分三档；共改动 20 处消费点。

归入判定范围本次改动
--bg-base 所有非卡片背景：窗口画布、侧栏 / 侧导航、页面主体、面板头、工具条、状态栏、表头、全屏覆盖层 10 处
--bg-elevated 唯一浮起层：卡片、弹窗、右键菜单、下拉、toast、浮动按钮 / 浮层面板 保留 24 处
+ 2 处误用归正
--bg-input 控件皮肤：输入框、下拉、标签胶囊、折叠条（非层级背景，是有独立语义的控件底色） 8 处

为什么控件单独一档？ 输入框 / 胶囊 / 折叠条不是"容器背景"，而是控件自身的填充色。项目里已有 --bg-input （20 处既有消费方）承担这一语义；若把它们也压到 --bg-base，会出现"同一个 App 里 18 个输入框是一种色、2 个是另一种色"的不一致。 因此这 8 处统一到既有控件令牌，而不是制造例外。

被删除的四个中间层级 —— --bg-panel / --bg-surface 及其 -solid 变体、--bg-sidebar 同族，在全库失去全部消费方后删除。 其中 --bg-sidebar 原本只是 --bg-panel 的别名（同值），是纯重复语义。

6 · 浅色主题终端可读性修复（保留项）

终端 ANSI 主题固定为暗色（前景 #e6edf3）且背景透明以透出底层。 浅色主题下底层为白色，导致终端文字几乎不可见：

修复前：#e6edf3 on #ffffff = 1.18:1（不可读）  →  修复后：#e6edf3 on --bg-terminal #17181c = 15.01:1

这一项刻意不收敛：--bg-terminal 不是"背景层级"，而是终端功能区的专用底。 深色系主题取各自底色（行为不变），浅色主题必须给深底 —— 与 VS Code 浅色主题保留深色终端的行为一致。 强行改为 --bg-base 会使终端文字在浅色主题下不可读。

8.1 两处失效设置项已移除

它们的共同特征是「写入无人消费的令牌」，即开关存在但完全没有视觉效果：

  • 侧边栏宽度（描述为"Work 模式左侧栏宽度"）—— 写入 --sidebar-width，全库无消费方；本项目也不存在该侧栏。
  • 紧凑模式 —— 写入 --spacing-* 四个令牌，全库无 var() 读取；其同时设置的 data-compact 属性也没有任何 CSS 选择器引用。

8.2 顺带修掉一处真实配色缺陷

AppearancePanel 用 var(--text-danger, #f85149)，但项目只定义了 --danger-text。--text-danger 从未存在，故实际一直取硬编码 fallback #f85149，不跟随主题（浅色主题下本应为 #c62828）。已改为正确的 --danger-text。

9 · 保留项（有意不动）

  • --bg-terminal —— 见第 6 节。功能必需，收敛它会造成可读性回归。
  • --bg-input / --bg-slider —— 控件皮肤与滑块轨道，不是层级背景，语义独立。
  • JS 按需注入的令牌（--gradient-alpha / --theme-gradient / --app-bg-opacity / --app-bg-overlay）—— 不在 CSS 中定义，其 var() fallback 才是默认值，必须保留。清理脚本按"仅移除已定义令牌的 fallback"规则正确跳过。
  • --rm-grid-cols —— 审计初报"失效引用"，复核确认为合法用法：由 RemoteManager 父元素定义、经 CSS 继承生效于子组件 ConnectionRow。已改进脚本识别组件内局部定义，消除误报。
  • 低使用令牌（读取 ≤2 处，32 个）—— 有消费方即非冗余。如 --titlebar-h / --status-success-border 均只被 1 处引用但语义关键。
