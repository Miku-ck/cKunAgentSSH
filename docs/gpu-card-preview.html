本页已作废（2026-09-21 补注）：本页「现状」区的条带 HTML 是手写拼出来的 （见生成脚本 nowHist()），并非真实组件输出 —— 因此它显示为彩色柱， 而当时应用里实际渲染的是 class="" 的空轨。手写标记掩盖了渲染层缺陷。 该缺陷（函数型 prop 默认值陷阱）已修复，真实渲染证据见 docs/nvstrip-fix-evidence.html。本页仅保留三套「进度条方案」的提案对比。

后续（同日）：本页的 方案 B（横向进度条 + 趋势薄条）已被采纳落地 —— 但趋势薄条由 7px 改为 4px，进度条统一 12px，趋势条改为统一暗色（不按阈值变色）。 GPU 卡行与 System 区已全部统一为同一形态（组件 NvGauge.ts，旧的竖向 NvStrip.ts 已删除）。落地效果与断言见 docs/nvgauge-evidence.html。 生成脚本 gen-gpucard-preview.cjs 已加拒绝运行的守卫。

8 · 需要你确认的点

  • 选哪个方案？（我推荐 A；若你舍不得每卡历史趋势，则 B）
  • "动态"指的是哪种？
    ① 数值变化时长度跟着变（已默认有，含 0.5s 平滑过渡）——
    ② 还是要在条体上加"流动/呼吸"之类动画效果？（终端风格里通常不要，会干扰读数）
  • 0% 怎么显示？ 现在是完全不填充（空轨）。要不要给一个最小可见宽度（如 1.5% 保底）？ 我倾向不给 —— 0% 就该是空的，保底反而会让人以为有占用。
  • System 区要不要一起换成进度条？ 那里宽度更大、且趋势更有意义（负载/内存的变化过程），我倾向保留条带、维持现状不动。
  • 阈值口径：本面板 66 / 90，与 DashboardView 顶部卡的 75 / 90 仍不一致 —— 要统一的话需同时改两处。
