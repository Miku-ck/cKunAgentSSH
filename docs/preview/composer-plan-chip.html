这是设计提案，不是渲染证据。页面里的工具条标记是我手写的（该形态在源码里还不存在，无法抽取）， 因此它只用于确认形态与色值，不能用来说明真实组件渲染正确。定稿后我会改真实组件， 那时再用产物 CSS + 真实 DOM 出证据页。
先说一个必须你定的语义冲突。你截图里「自动审批」和「计划」是并排两个控件， 但我上一轮在后端实现的 permission_mode 是互斥枚举 Literal["normal", "plan"] —— 它俩是同一根轴上的两个取值。 并排摆会暗示两个独立维度，用户同时打开就会得到 「已在计划模式，但自动审批其实不生效」的矛盾态 （实现上 PlanModeGuard 优先级 6 早于 PermissionGate 8，写操作被直接拒绝， 连审批卡都不会弹）。所以下面给两个方向，请选一个。

方向 A：一个选择器（推荐）

权限模式收敛成一个下拉，绿 chip 只表达「当前所处模式」。这与 Claude Code 的 Shift+Tab 循环一致，也与后端已实现的互斥枚举一致 —— 前端零额外契约。

两行反面证据，都是真算出来的：浅色直接套 #4ec9b0 只有 1.88:1（正文不可读）； 而复用既有 success 色 #1e7e34 也只有 4.49:1 —— 差 0.01 压线不过 （手算纯白底是 5.13:1，漏了 chip 自身底色会把对比拉低）。故浅色定 #166534，留出余量。 这是本次唯一必须新增令牌的理由。

需要你定的 4 件事

  • ① 方向 A 还是 B？（一个选择器 / 两个独立控件）—— 决定后端契约是否要改。
  • ② 若是 B，「自动审批」下拉的选项集是什么？仓库里已有审批白名单（permission-policy）、 授权 scope（once/session/always）、环境（test/prod）三套概念，得明确它接哪一个。
  • ③ 麦克风要不要做？全仓搜索「麦克风 / 语音 / voice / mic」零命中 —— 截图里那个是参考产品的功能，本项目没有，属于新功能不是改样式。
  • ④ + 菜单里的「计划」保留吗？工具条上常驻后会形成双入口。 建议保留（菜单=能力总览，工具条=高频快捷），两者同源 activeCaps 天然同步。

顺带两个形态差异（我建议不照抄）

  • 截图里 + 按钮有边框（本页方向 B 第一条就是这个 .ringed 变体）； 但项目里 .plus-btn 与 .toolbar-btn 都是无边框、hover 才出底色。 单独给 + 加边框会变成三个按钮三种皮肤。建议保持无边框。
  • 截图「自动审批」用的是圆圈图标；我改成盾牌，因为该控件表达的是授权策略。 要照抄圆圈也可以，图标不改逻辑。
